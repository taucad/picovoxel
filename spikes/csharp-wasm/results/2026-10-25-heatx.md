# Results, 2026-10-25: Helix heat exchanger

LEAP 71's [Helix heat exchanger](https://github.com/leap71/LEAP71_HelixHeatX) at `a0a0234e`, compiled from its
unmodified source with the same build as the gyroid sphere. Machine: the project's cloud container, 4-core x64,
Linux, glibc 2.39. Voxel size 0.5 mm, one run each. Raw output: `heatx-native.txt`, `heatx-node.txt`,
`heatx-chromium.txt` and `math-probe.txt`.

## Correctness

The program writes a 502,880,684-byte STL with 10,057,612 triangles. The digests are FNV-1a over the STL file's
bytes and over the final mesh's vertices and triangles.

| Build | Volume, mm³ (bits) | STL digest | Mesh digest |
| --- | --- | --- | --- |
| native .NET, system float trig, 4 cores or 1 | 719572.250 (`492fad44`) | `7714166db2385cde` | `a654667cf3267d5e` |
| wasm, musl float trig | 719572.250 (`492fad44`) | `38ff99b466c83cc1` | `366cd46e2611fca5` |
| native .NET with `float-trig.so` preloaded | 719572.250 (`492fad44`) | `b9dac944dc434a69` | `2a13ca3e320a6075` |
| wasm with `float-trig.o`, Node and Chromium 153 | 719572.250 (`492fad44`) | `b9dac944dc434a69` | `2a13ca3e320a6075` |

The first wasm build matched the volume to the bit and the triangle count, but not the vertices. The cause is
float trigonometry. .NET's `MathF.Sin`, `Cos`, `Tan`, `Atan`, `Atan2`, `Asin` and `Acos` call the C library:
glibc natively and Emscripten's musl in wasm. Over 1M inputs the two give different bits for all seven functions
(`math-probe.txt`). The double functions, `Pow`, `Exp`, `Log` and `Sqrt` agree. The gyroid sphere uses only
double trigonometry, which is why it matched without the fix.

`libm/float-trig.c` defines the seven functions as `(float)f((double)x)`. It is linked into the wasm module and
preloaded natively, and with it the 503 MB STL is byte-identical across native, Node and Chromium. Native
thread count does not change the output.
